# Analysis code behind the supplementary studies

The scripts are the ones that produced the paper's numbers, with the authors' absolute paths replaced by repository-relative ones (`REPO` = the repository root, data under `data/`, run outputs under `<Model>/Bhopal/outputs/` and `<Model>/cross_data_testing/outputs/`). Their `results/` folders carry the outputs they produced for the paper, so every table can be checked without re-running anything. Python dependencies beyond the training environment: `shapely` and `geopandas` (installed by `setup_venv.sh`).

| folder | study | scripts |
|---|---|---|
| `leakage/` | spatial overlap between splits and whether it inflates the benchmark (supplementary "Spatial Overlap Between Splits") | `leakage_analysis.py` (trajectory proximity, observed-area overlap, map and CDF figures; needs the survey-path GeoPackages, not in the v1.0 data release), `partition_test_scenes.py` (the leakage-free test subset; its output is shipped as `data/Bhopal/splits/leakage_free_test_partition.csv`), `rescore_predictions.py --exp-dir <Model>/Bhopal/outputs/<run> --label <name> [--classes 21]` (re-scores a run's cached test predictions on the disjoint and overlapping subsets and checks the full-test number against the log), `make_summary.py` |
| `factor_attribution/` | which property of BhopalMLS drives the transfer asymmetry (supplementary "Factor Attribution") | `build_ablation_subsets.py` (the four equal-budget training subsets; output shipped in `data/Bhopal/`), `make_ablation_configs.py` (writes the B1 to B4 configs from a fine-tuning config; shipped under `<Model>/Bhopal/configs/bhopal/`), `collect_perclass_transfer.py` and `collect_ablB_crosseval.py` (parse the test logs of the cross-region runs into the attribution table), `analyze_ablB_attribution.py` (the in-domain-normalised reading and the Vehicle-dropped control) |
| `coral/` | post-hoc CORAL domain adaptation BhopalMLS -> Paris-Lille-3D on frozen fine-tuned encoders (supplementary "Post-hoc CORAL Domain Adaptation") | `run_all.sh [--smoke]` runs `extract_features.py`, `coral_align_and_train.py` and `eval_coral.py` for Concerto and Utonia; CPU only |
| `class_imbalance/` | the five-cell recipe ablation (class weights, Lovasz loss, Building downsampling) | configs under `{Utonia,Concerto}/Bhopal/configs/bhopal_ablations/`; the C4 cell needs the full-Building scene file built by `class_imbalance/build_full_building_h5.sh` |

The log collectors read the layout of this repository, which is the one the paper's runs used: in-domain runs in `<Model>/Bhopal/outputs/<run>/`, transfer evaluations in `<Model>/cross_data_testing/outputs/<source>_on_<target>/ft_9ch/` (Concerto(L) runs carry the `_indoor` suffix the launcher adds for the `indoor` keyword).
